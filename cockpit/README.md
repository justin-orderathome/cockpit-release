# cockpit

Claude Code 的右側面板 mod。上方的「狀態」框顯示用量、目前的模型與思考深度，以及 agent 是不是在等你；下方的框用四個分頁放任務進度、常用 prompt、skill 清單與設定。

```
╭─ 狀態 ─────────────────────────────────────────────────────╮
│ CTX 54%  ██░░ 544k/1M   5H 23%  █░░░ 2h10m   WK 12%  ░░░░  │
│ 模型 opus ▾   深度 high ▾                                  │
│ ● 等你核准：Bash `git push origin main` · 14:02 起         │
╰────────────────────────────────────────────────────────────╯
╭─ 任務 3/5 ─ 2: 基本 ─ 3: SKILL ─ 4: 設定 ──────────────────╮
│ 3/5 完成 · 還需約 4m                                       │
│ ✓ 讀取設定檔                                          1m × │
│ ● 實作分頁                            ███░░░  52%    ~2m × │
│   ● 找出所有呼叫點                 haiku · medium  1m12s × │
│   ✗ 查 API 文件                                      40s × │
│ ○ 寫測試                                             ~3m × │
╰─ c: 清除已完成 ──────────────── k: 上頁  1/2  j: 下頁 ─────╯
```

顏色只在需要注意時出現：框線、已完成與還沒開始的項目都是暗色，強調色留給目前的分頁、進行中的項目與「繼續」，警告色留給「等你決定」這類要你動手的事。除了強調色可以自己選，其餘顏色都跟著終端機主題走。

用 Claude Code 2.1.294 的 function hooks（plugin 的 hooks module）寫成，沒有任何外部相依。

## 功能

### 上方：用量、模型與深度

- **用量**：`CTX`（上下文）、`5H`（5 小時額度）、`WK`（本週額度）。未達黃色門檻時跟一般文字同色，到黃色門檻轉成主題的警告色，到紅色門檻轉成錯誤色。用 API key 時只有 CTX。
  - 進度條後面各有一段文字：CTX 是「已用／窗口」的 token 數（`544k/1M`），5H 是重置倒數（`2h10m`），WK 是重置日期（`10-14`，電腦的當地時區）。數字都直接取自 Claude Code，跟 `/context` 與狀態列一致。
  - 面板不夠寬時，這三段文字依序隱藏：先是 WK 的日期，再來 5H 的倒數，最後 CTX 的用量。都藏了還放不下，才改成一項一行，這時文字全部顯示。面板 67 欄以上三段都看得到，62 欄時看得到前兩段。
- **模型、深度**：在用量下方的兩個下拉選單，選了就執行 `/model`、`/effort`。深度顯示實際送出的值；被模型降級時，旁邊會加灰字 `(選 max)`。
- **提醒**：任一項用量剛跨過 toast 門檻時跳一次 toast，同一個額度時段內不重複。
- **在等你**：agent 停下來、要你動作才會往下時，模型那一行下面多一行，回到畫面一眼就知道它是還在做、還是在等你（見下方說明）。沒有在等時不多這一行。

**在等你**（狀態框）：分兩種，寫法和顏色不同。

| 狀態 | 什麼時候 | 那一行 |
| --- | --- | --- |
| 等你決定（警告色） | 一輪還沒結束、畫面真的跳出對話框：權限核准、AskUserQuestion、核准計畫、MCP 的 elicitation。主對話與 subagent 都算 | `` ● 等你核准：Bash `git push origin main` · 14:02 起 ``<br>`● 等你回答：要用哪個資料庫？ · 14:02 起`<br>`● 等你核准計畫 · 14:02 起`<br>`` ● subagent「找檔案」等你核准：Bash `ls -la` · 14:02 起 ``<br>`● 等你回答：github「要建到哪個 repo？」 · 14:02 起`（MCP elicitation：伺服器名稱與訊息的第一行） |
| 輪到你（暗色） | 主對話一輪結束，等你的下一個 prompt | `輪到你 · 14:02 起` |

- **寫什麼**：權限核准後面接工具內容：Bash／PowerShell 是指令的第一行，檔案類工具是路徑，其他工具只寫工具名稱。AskUserQuestion 只寫第一個問題。subagent 跳出的對話框寫它在 [任務] 上的描述，同時 [任務] 那一列的圖示換成警告色 `?`（見下方「subagent 列」）。auto 模式交給分類器、沒有跳出對話框的不算。
- **只寫開始時間**：不跑「已等幾分鐘」的計時，面板閒置時不做任何事。
- **好幾個同時在等**：只寫最早開始的那一個，後面加「 · 另 N 個」（以 loop 計）。等你決定優先於輪到你：subagent 停在對話框、主對話那一輪已經結束時，寫的是 subagent 的等你決定。
- **什麼時候消失**：等你決定在你回應對話框、那個 loop 接著往下走時消失（核准、拒絕、回答、按 Esc 都算；按 Esc 中斷主對話那一輪時，換成輪到你）；subagent 結束（包括被停掉）時它的也一起拿掉。輪到你在你自己送出 prompt 時消失；subagent 或背景工作的通知叫醒主對話不算你回來了，輪到你照樣留著。主對話的一步、一輪結束或新 prompt 都不會清掉 subagent 的等你決定。
- **窄的時候**：一定保留「● 等你…」與「另 N 個」，依序拿掉工具內容、開始時間；還放不下，就截 subagent 的描述（`● subagent「找出 chipA…」等你核准 · 另 1 個`），不從行尾截。輪到你那一行照一般規則截尾巴。
- **不發通知**：cockpit 只負責你回到畫面時看得到，不跳 toast、不響鈴；Claude Code 自己已經有通知。這一行沒有開關。`/clear` 或 resume 之後重新算起。

### 下方：四個分頁

面板在側邊時，下方的框撐到面板底，說明區貼著框的下緣：說明區的行數照分頁裡最長的那一則說明反算（至少 5 行，最多到放得下），多出來的空白留在列表與說明區之間。面板在輸入框上方（inline）時維持內容的高度。每個分頁的操作（例如 [基本] 的 `e: 編輯 r: 重新載入`、[SKILL] 的 `o: 開關 u: 更新用法`、[任務] 的「任務」子分頁是 `c: 清除已完成`、「路線圖」子分頁是 `d: 已完成 effort N r: 重新載入路線圖`、「背景」子分頁是 `c: 清除已結束`）都疊在下框線的左端，翻頁鍵在右端；面板太窄、兩者放不下時，操作退回框內的最後一行。組名加粗、個數暗色；橫向排成幾欄時，欄與欄之間有一條暗色直線。

| 分頁 | 內容 |
| --- | --- |
| **任務** | TodoWrite 與 TaskCreate／TaskUpdate 的任務清單。每列有耗時或剩餘時間，進行中的那一列另外畫進度條與百分比，超時時時間變紅。主對話派出的每個 subagent 各有一行 subagent 列，掛在派出它的任務底下，用的模型或深度跟主對話不同時在行尾標出來（見下方說明）。主模型是 Opus／Sonnet 5.5 這類新模型時，Claude Code 預設不給任務工具（TaskCreate、TodoWrite），模型寫不出清單；這時「任務」子分頁最上面多一行黃字，提示在 settings 的 `env` 加 `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`，加了不用重開 session，下一次送出 prompt 後提示就消失。分成「路線圖」「任務」「背景」三個子分頁，一次看一種：打開 [任務] 預設在「任務」，按 `m`／`t`／`b` 或點分頁籤切換，切到別的分頁再回來停在上次看的子分頁（同一個 session 內）。分頁籤帶數字：路線圖是列出的 effort 數，任務是主清單的進度 `n/總數`（主對話沒有任務、只有 subagent 時是 subagent 數），背景是還沒結束的背景工作數（執行中加排程中），有東西在跑時加 `●`；面板窄時只留名稱與 `●`。沒有 effort 時不畫路線圖分頁籤，沒有背景工作時不畫背景分頁籤，只剩「任務」時整行分頁籤不畫；正在看的子分頁變空時跳回「任務」。「背景」子分頁列出這個 session 的背景工作（背景 shell、Monitor、Workflow、MCP task、CronCreate 的排程與 `/loop` 的喚醒），分「執行中」「排程」「已結束」三段，已結束的只列最近 5 筆、更早的收成「▸ 更早的 N 筆」；按 `c` 清除已結束，× 單獨隱藏一列。「任務」子分頁最上面只留「還需約」（有預估時才有），會自動翻到最近開始的進行中任務或 subagent 列，手動翻頁後停止，任務有變化時恢復；自動跟隨永遠不替你換子分頁，看路線圖時不會被拉走。「路線圖」子分頁列出本專案每個 effort 的階段與進度（見下方說明） |
| **基本** | 常用 prompt，讀自 `~/.claude/cockpit/prompts.md`。點了填進輸入框，名稱結尾標 ` !` 的會直接送出。prompt 裡可以寫 `{{票}}`、`{{分支}}`，填入或送出時換成當下的值（見下方「prompt 變數」）。列上只顯示名稱，滑鼠移到項目上，列表下方的說明區會顯示完整內容（原文，變數不代換） |
| **SKILL** | 已安裝的 skill，依 plugin 分組；用 `npx skills add` 裝的依來源（`owner/repo`）分組，另有「我的 skill」「內建 skill」兩組（見下方說明）；在「SKILL 覆寫」寫了 `categories` 時，頂端多一排分類分頁籤，一次看一個分類，選中那個分類的 token 數接在同一列右端。點了把 `/<skill 名稱> ` 填進輸入框。一組裡的 skill 名稱橫向排成等寬的幾欄，欄數隨面板寬度變（1–5 欄，每欄至少 18 格），由上到下排滿一欄再換右邊一欄，比一欄還寬的名稱多佔一欄（可在 [設定] 改回一個一行）；滑鼠移到名稱上，列表下方的說明區會顯示完整說明。說明會自動翻成繁體中文。cockpit 還會讀每個 skill 的 SKILL.md，整理成四項用法（何時用、怎麼叫、會做什麼、搭配）：有用法的 skill，滑鼠停在名稱上時後面出現一個 `?`（平常藏著，面板矮到沒有說明區時照常顯示），點了把列表換成用法頁，上面是說明與用法的全文，可以直接填入或返回（見下方說明）。用法頁上還可以按「教學」，讓 cockpit 把這個 skill 寫成一份詳細的繁體中文教學，在編輯器裡打開（見下方說明）。按 `o` 進開關模式，可以把單一 skill、整組或整個分類從模型的清單拿掉，並看到各佔多少 token 與叫用過幾次（見下方說明），關掉的 skill 與組在列表裡變暗。主對話正在用的 skill，名稱前面標 `●`（見下方「叫用次數與正在用」） |
| **設定** | 強調色、用量門檻、自動開啟等參數；作者有附範本時，下框線右側有「套用範本」（見下方「範本」） |

**subagent 列**（[任務]）：主對話（或 subagent）用 Agent 工具派出 subagent 的那一刻，[任務] 就多一行，不管它有沒有寫 TodoWrite 清單；fork、subagent 再派出的，以及帶名字（`name`）派出的 teammate 也算；teammate 一輪做完閒著時打勾，收到訊息醒來又回到進行中。workflow 的 agent 不列。

- **一行的內容**：狀態圖示、描述、模型標示、耗時、×。圖示 `●` 是進行中（在等它派的子 agent 回報也算進行中），`✓` 是完成，`✗` 是被停掉或出錯（差別寫在說明區），警告色的 `?` 是它跳出了對話框、在等你決定（同時狀態框寫「● subagent「<描述>」等你核准…」，見上方「在等你」）；你回應之後它往下走，圖示就回到 `●`。耗時從第一次派出算到真正結束，同一個 subagent 等完子 agent 醒來接著跑時不重新計時。沒有進度條與百分比，也不算進「還需約」。
- **掛在哪裡**：派出那一刻派出者正在進行的任務底下；主對話沒有進行中的任務時接在清單最後；subagent 再派出的接在派出者那一列底下，最多三層。寫了清單的 subagent，任務接在它那一行底下，這一行的描述後面加 `done/total`。
- **結束之後**：留在原處、整列變暗。按 `c`（清除已完成）時，完成、被停掉、出錯的 subagent 列連同它底下的任務一起清掉；× 單獨隱藏一列。主對話沒有任務、只有 subagent 時，「任務」子分頁籤寫 subagent 的數量。
- **說明區**：滑鼠移到 subagent 列上，說明區顯示：`subagent「<描述>」 · <類型>`、`<完整 model id> · <深度> · <狀態> <耗時>`、`prompt：<派工 prompt 的前三行>`。在等你決定時，狀態寫「等你核准」「等你回答」或「等你核准計畫」；進行中而且正在用某個 skill 時，狀態下面多一行 `用 <skill>`（見下方「叫用次數與正在用」）。

```
  ? 找出所有呼叫點                 haiku · medium  1m12s ×
── 說明 ──────────────────────────────────────────────────
subagent「找出所有呼叫點」 · Explore
claude-haiku-5-5 · medium · 等你核准
prompt：找出 chipA 的所有呼叫點…
```

**模型標示**（[任務] 的 subagent 列與路線圖上經手的票共用）：subagent 用的模型或深度跟主對話不同時，行尾靠右標「haiku · medium」這樣的別名與深度；跟主對話完全一樣的不標，一眼看得出哪些工作交給了別的模型。

- **跟誰比**：主對話最近一次用的模型與深度，用 `/model`、`/effort` 換了之後跟著換基準。subagent 這一邊也看它最近一次的模型與深度，中途換了模型（例如 fallback）標示就跟著變；剛換模型、深度還不知道時先只寫別名。
- **寫法**：別名取自 model id 的 `claude-<別名>-…`；只有深度不同也寫完整的「opus · high」，一欄上下對得齊。認不出別名的 id 照原樣寫（太長截短）。標示用一般文字色，不用強調色；結束的列整列變暗，標示跟著暗。
- **窄的時候**：同一塊（[任務] 清單算一塊、路線圖算一塊）裡只要有一列放完整的寫法後名稱會少於 8 欄，整塊都改成 4 欄的縮寫，例如「S·hi」（字母 O／S／H，認不出寫 `?`；深度 lo／md／hi／xh／mx）。縮寫了名稱還是少於 8 欄的那一列不標，名稱永遠讀得出來。

放不下時，下方會自己分頁，翻頁鍵嵌在下框線的右端（`k: 上頁  2/5  j: 下頁`），上方的「狀態」框會一直留在畫面上。面板太窄、分頁列放不上框線時，分頁列會退回框上方的一行。

**路線圖**（[任務] 上方）：讀目前專案 `.scratch/` 底下 mattpocock-skills 的本機 tracker 檔案（`map.md`、`spec.md`、`issues/NN-*.md`；目錄可以不是 `.scratch/`，見下方「effort 放在哪」），每個 effort 一行，顯示階段、進度與「繼續」按鈕；點名稱展開看票（只列還要做的：已結案的票有 2 張以上時收成一行「▸ 已結案 N」，整組都結案的決策票或實作票只剩小計那一行，點一下攤開；手動攤開或收起的只記到這個 session 結束），點票用 VS Code 開檔，滑鼠移到票上，下方說明欄顯示它的問題或要做的內容；結案的決策票改成顯示決定了什麼（見下方「決策的要點」）。

| 階段 | 條件 | 「繼續」填入 |
|---|---|---|
| 找路中 | 有地圖，還有沒結案的決策票，或「Not yet specified」還有內容（整行括號的註記不算） | `/mattpocock-skills:wayfinder <map.md>` |
| 待寫規格 | 地圖已抵達，沒有 `spec.md` | `/mattpocock-skills:to-spec <map.md>` |
| 待拆票 | 有 `spec.md`，沒有實作票 | `/mattpocock-skills:to-tickets <spec.md>` |
| 實作中 | 有沒結案的實作票 | `/mattpocock-skills:implement <第一張可接手的票>`，並請它完成後把 `Status:` 改成 `resolved` |
| 已完成 | 票全部結案（預設不顯示，按下框線的「已完成 effort N」展開） | — |
| 零散 | 沒有地圖與規格書的票 | 有 `needs-triage` 的票時填 `/mattpocock-skills:triage` |

開頭有 `Type:`（research／prototype／grilling／task）的是決策票，其餘是實作票。實作票的 `Status:` 是 `resolved`、`done`、`wontfix`，或驗收清單全部打勾，就算結案。`Status:` 是 `ready-for-human` 的票標成「待人處理」，「繼續」會跳過它，只剩這種票時不填任何東西。agent 用 Write／Edit 改了 `.scratch/` 底下的檔案會自動重讀；用 Bash／PowerShell 改的，指令跑完後比對檔名、大小與修改時間，有變才重讀。自己在編輯器改的，按 `r`（下框線的「重新載入路線圖」）重新讀取。「已完成 effort N」與「重新載入路線圖」放在下框線而不是「路線圖」那一行：[任務] 會自動翻到進行中的任務，那一行常常不在畫面上的這一頁。

**決策的要點**（路線圖）：結案的決策票，滑過時說明區不再顯示當初的 Question，而是那一題最後定了什麼，不用點開檔案就能回想。說明區只放一則，依序找第一個有的：

1. 地圖的 Decisions so far 有一行連到這張票 → `已定：<要點>`
2. 地圖的 Out of scope 有一行連到這張票 → `不做：<要點>`
3. 票的 `## Answer` 第一段（跳過開頭的套話行：只有日期、以「…定案：」結尾，或日期開頭只有一句，例如「2026-10-21 與作者談定（grilling，兩輪）。」），最多 5 行，超過時結尾寫「…」
4. 連 Answer 都沒有 → 照舊顯示 Question

```
  ▾ 決策 3/4
    ▾ 已結案 3
    ✓ 01 欄位怎麼排
    ✓ 02 分頁要不要拆
    ✓ 03 要不要發通知
    → 04 窄的時候怎麼截
── 說明 ──────────────────────────────────────────────────
已定：用三欄，窄的時候退成兩欄
```

- **怎麼對上票**：只看那兩段裡每一行開頭的 `[標題](路徑)` 連結，跟「經手」一樣用路徑或檔名（`NN-<slug>.md`）比對，斜線方向、`./` 前綴都對得到。要點取連結後面第一個 `：` 或 `:` 之後的字（沒有冒號就整行），去掉 `**`，連結只留文字，反引號照留。同一張票出現好幾行時取第一行；兩段都有時取 Decisions so far。沒有地圖的 effort 直接看 Answer。
- **不放全文**：說明區的高度是照整個分頁最長的那則說明算的，放全文會讓說明區一直撐到最高；要點照說明區的規則長高，到放得下的上限為止，超過時最後一行結尾寫「…」。要看完整的理由就點票開檔。
- 實作票照舊顯示 What to build，沒結案的決策票照舊顯示 Question；「▸ 已結案 N」那一行沒有預覽，攤開後滑過各張票才看得到。已完成的 effort（按 `d` 展開）用同一套規則。有人經手的票，最前面「誰在做」那一行照舊。地圖或票檔改了，跟著路線圖一起重讀。

**誰在做這張票**（路線圖）：這個 session 裡主對話或某個 subagent 經手的、還沒結案的票，看得出是誰在做。經手的意思是下面任一種：你送出的 prompt 寫了這張票的路徑（包括按「繼續」填進去的，所以 `/implement <票>` 一送出就算）、派 subagent 的 prompt 寫了它的路徑、某個 loop 用 Write／Edit 改了票檔、或 Bash／PowerShell 的指令裡有票的路徑。只「讀」票不算；subagent 回報給主對話的通知裡寫了路徑也不算。比對只認路徑或檔名（`NN-<slug>.md`），斜線方向、相對或絕對路徑都對得到，光寫編號或標題不算；別的專案或別的 effort 底下的同名票不算。

- **畫在哪**：subagent 經手的票在行尾（「等 01」後面）標那個 subagent 的模型與深度，規則和 [任務] 一樣：只標跟主對話不同的，放不下時整個路線圖一起改縮寫。主對話經手的票不標模型（一定跟主對話相同）。
- **說明區**：滑鼠移到票上，原本的問題或內容前面多一行「主對話在做」或「subagent「<描述>」在做」。
- **換人與拿掉**：一張票先後被幾個 loop 經手，顯示最近的那個。票結案就不再標；經手的 subagent 結束時拿掉；主對話經手的留到票結案或 session 結束。經手只記在這個 session，不寫進票檔；別的 session 認領的票照舊只顯示已認領。

**effort 放在哪**：照專案的 `docs/agents/issue-tracker.md`（寫票的 skill 也看這份），取裡面第一個 `<目錄>/<effort>/` 這種路徑的目錄，例如寫 `docs/efforts/<effort>/map.md` 就讀 `docs/efforts/`。沒有這份文件或認不出路徑時讀 `.scratch/`；文件標題寫明是 GitHub、GitLab、Linear、Jira 這類線上的 tracker 時不顯示路線圖。目錄一律從專案根目錄找，shell `cd` 到別處不影響。

**用 `npx skills` 裝的 skill**（[SKILL]）：`npx skills add <owner/repo> -g` 把 skill 一個一個放進 `~/.claude/skills/`，Claude Code 看到的是一個個個人 skill，不知道它們是同一包。cockpit 讀 `npx skills` 記下的 `~/.agents/.skill-lock.json`，把查得到來源的 skill 依來源分組，例如 `emilkowalski/skills` 一組；只有一個 skill 的來源也自成一組。來源組和 plugin 組一起照字母排，組名可以在「SKILL 覆寫」改短。查不到來源的（自己寫的、claude.ai 同步的、其他工具裝的）留在「我的 skill」；沒有這個檔或讀不懂時，全部照舊在「我的 skill」。比對只看 skill 名稱，lock 檔跟著 skill 清單一起重讀（裝了新的 skill 後 `/reload-plugins` 或重開）。裝在專案裡的（不加 `-g`）也一樣分組：來源記在專案根目錄的 `skills-lock.json`，cockpit 一併讀進來；同一個 skill 全域和專案裡都有記錄時，照全域的來源，因為同名時生效的是使用者層那一份。

**開關**（[SKILL]）：每個 skill 的名稱與說明都會放進模型看到的 skill 清單，每次對話都要付這份 token，相近的 skill 多了模型也容易叫錯。按 `o`（或點下框線左端的「開關」；`o` 在任何一頁都有效）進開關模式：組全部展開，每個 skill 一行，行尾是它被叫用過幾次（見下方「叫用次數與正在用」）、它在清單裡佔的 token 數（估計值，取自用量明細；沒列進清單的沒有數字）與 `[ 開 ]`／`[ 關 ]`；再按 `o` 或點「完成」回到平常的樣子。

```
▾ 內建 skill (3)                                 1240 [ 部分 ]
  simplify              3 次 · 最後 10/21         412 [ 開 ]
  code-review           沒用過（自 10/1 起）      388 [ 開 ]
  security-review       1 次 · 最後 10/14         440 [ 關 ]
```

- **整組、整個分類**：開關模式裡每組的行尾是那組開著的 skill 的 token 合計與組的開關；有分類時，分類標題列下面多一列「整個分類」與它的開關。組與分類的開關不另外記，由底下的 skill 算出：全開是 `[ 開 ]`、全關是 `[ 關 ]`、其餘是 `[ 部分 ]`。按下去時，開或部分就把開著的全部關掉，關就全部打開，一次寫進 `skillOverrides` 的好幾個鍵；整組關掉後再單獨打開一個，組就顯示「部分」。提示寫明名稱、關了（或開了）幾個 skill 與 token 數。分類只算非 plugin 的 skill：整個分類的開關不停用 plugin，分類裡有 plugin 組（含停用後空了的）時，關掉後的提示會說「另有 N 個 plugin 組沒動，要停用請按該組」。
- **token 數**：分類標題列寫 `<分類>：<開的數>/<總數> 開 · <N> tokens`，不進開關模式也看得到；N 是開著的 skill 的合計，看得出關哪個最划算。不在用量明細裡的 skill 不算進去，一個都不在時不寫 token。
- **關掉之後**：模型當下就叫不到它，你仍然可以自己打 `/名稱` 叫用。清單的 token 要從下一個 session 起才省下來，這個 session 已經送出的清單與已經載入的內容不受影響；按完會跳提示說明這幾件事。
- **平常模式**：關掉的 skill 照樣列出、搜得到、點了照樣填入，只是變暗。整組或部分關掉的組，組名變暗、行尾標「已關」「部分關」；整個分類關掉或部分關掉時，分類分頁籤加「·關」「·部分」。
- **存在哪裡**：目前專案的 `.claude/settings.local.json` 的 `skillOverrides`，關寫 `"user-invocable-only"`、開就刪掉那個鍵；檔案裡其他設定原樣保留。這和 Claude Code 的 `/skills` 選單是同一份設定，兩邊改的互相看得到（在 `/skills` 改過之後，切到別的分頁再切回 [SKILL] 就會重讀）；值不是 `"on"` 的都算關。開關只影響這個專案，新的專案預設全開。檔案不是合法的 JSON 時 cockpit 不寫，跳提示請你自己檢查。
- **不進版控**：`settings.local.json` 是個人設定。cockpit 第一次建立這個檔時，若專案的 git 沒有忽略它，會把 `**/.claude/settings.local.json` 加進這個 repo 本機的忽略清單（`.git/info/exclude`，不改要 commit 的 `.gitignore`），並跳提示。
- **plugin 的 skill 沒有單獨的開關**：Claude Code 的 `skillOverrides` 管不到 plugin，只能整個停用 plugin。claude.ai 同步的 skill 可以單獨關。
- **停用整個 plugin**：開關模式裡，plugin 組（照來源分組替那個 plugin 開的組，底下全是它的 skill）的行尾是 `[ plugin 開 ]`，停用後是 `[ 停用整個 plugin ]`，和一般的開關看得出不同；裡面的 skill 一樣一個一行、行尾是 token 數，但沒有開關。按下去是在這個專案停用整個 plugin，**連它的指令、hook、agent 一起停**；再按一次啟用。寫在同一個 `settings.local.json` 的 `enabledPlugins`：停用寫 `"<plugin>@<marketplace>": false`，啟用刪掉那個鍵（完整的鍵從 Claude Code 記的已安裝 plugin 清單 `~/.claude/plugins/installed_plugins.json` 查）。同一個 plugin 從幾個 marketplace 裝時，任一個鍵是 `false` 就算停用：停用時已經有就不再寫，啟用時把它是 `false` 的鍵全部刪掉。plugin 的開關要重新載入才生效，cockpit 改完會代你跑 `/reload-plugins`（這會連 cockpit 自己一起重新載入），提示寫明 plugin 名稱與已代跑；設定檔本來就是那個狀態（沒有改）時不代跑，提示會說明。停用後它的 skill 不在清單裡了，組照樣列著（空的），在平常模式變暗、標「已關」，開關模式裡按得到「啟用」。cockpit 自己不能從這裡停用。**整個分類的開關不會停用 plugin**：只想關 skill 時不會連 `/impeccable` 這類指令都失去；要停用請按那一組。用 `move` 把 plugin 的 skill 混進一般的組、或收進自訂組（就算收了它的全部 skill）時，那一組都不是 plugin 組，沒有 plugin 的開關，裡面的 plugin skill 跟著它的 plugin 變暗。

**叫用次數與正在用**（[SKILL]）：cockpit 記下每個 skill 被叫用幾次、最後一次是哪天，要關掉不用的 skill 時有個依據；也標出現在正在用哪一個。

- **叫用**：skill 的內文被展開給模型一次就算一次。你手打 `/名稱`（後面帶參數也算）與模型自己用 Skill 工具叫（主對話或 subagent）都算，不分開；預先載入 subagent 的不算。同一個對話裡已經載入過、模型再叫時 Claude Code 只回「已經載入」、沒有再給內文，這次也不算。plugin、內建與 MCP 的 skill 一樣記。
- **在哪看**：開關模式裡，有開關的 skill 在 token 數左邊多一欄 `12 次 · 最後 10/21`，對齊成一欄，名稱長的讓位截短。平常模式不佔列上的位置，滑過時寫在說明欄標題的提示裡，接在版號後面：`── 說明 · v1.3.1 · 10-14 · 12 次 · 最後 10/21 · 點 ? 看用法（4 項） ──`。沒有開關的（plugin 的 skill）只看得到這裡。
- **沒用過**：寫「沒用過（自 10/21 起）」。日期取 cockpit 開始記錄的那天與這個 skill 版號的更新日期，兩者較晚的那個，剛裝或剛更新的不會看起來像放了很久；查不到更新日期就用開始記錄日。開始記錄日是裝了這一版 cockpit 後第一次開的那天。
- **存在哪裡**：cockpit 自己的狀態（`$.store` 的 `skillCalls`），全域、跨 session、不分專案。解除安裝或改名的 skill 紀錄不清（不顯示，裝回來接著算），也沒有歸零的功能；排序不因次數改變。好幾個 session 幾乎同時叫用時可能少算一次。
- **正在用**：主對話正在用的 skill，列表裡名稱前面的位置換成強調色的 `●`；它在收合的組裡時，組名列也帶記號，寫在 `▸` 後、組名前（`▸ ● commit-commands (4)`），攤開後換到名稱前。subagent 正在用的寫在它那一列的說明區（`用 <skill>`），[SKILL] 不標。狀態框不加。
- **什麼時候結束**：主對話的在這一輪結束、下一個 skill 被叫用或你送出新 prompt 時結束，取先到的；subagent 的在它結束或叫用下一個時結束。背景工作的通知叫醒主對話不算新 prompt。不計時，也不會逾時。`context: fork` 的 skill 跑在沒有 subagent 列的 agent 裡，次數照算，但不標正在用。

```
▸ ● commit-commands (4)
▾ 我的 skill (3)
  › caveman        ● tdd           › wayfinder
```

**填入輸入框的規則**（[基本] 與 [SKILL] 共用）：輸入框是空的就直接填；已經有字時，slash command 會放在最前面，原本的字變成它的參數，一般 prompt 則換一行接在後面。

### 剩餘時間怎麼算

cockpit 會在 system prompt 加一段要求，請模型在每個任務名稱後面寫上預估時間 `(~Nm)`。剩餘時間 = 預估 × 校正係數，係數是已完成任務的「實際 ÷ 預估」，限制在 0.25–4 之間。沒有預估的任務，用已完成任務的平均耗時。

## 安裝

需要 Windows、Claude Code 2.1.294 以上（用 `claude --version` 確認）與 `git`（用 `git --version` 確認；沒有的話在 PowerShell 執行 `winget install Git.Git`，裝好後重開 PowerShell）。cockpit 從公開的發布 repo `justin-orderathome/cockpit-release` 安裝。

1. 在 PowerShell 執行：

   ```powershell
   claude plugin marketplace add justin-orderathome/cockpit-release
   claude plugin install cockpit@orderathome
   ```

   第一行把發布 repo 加成名為 `orderathome` 的 marketplace，第二行從它安裝 cockpit。
2. 把所有 Claude Code 視窗關掉再開。右側會出現面板；切到 [設定] 捲到最下面，看得到 `cockpit` 與版本號就是裝好了。面板沒有自己出現時打 `/cockpit`。

第一行失敗時，先執行 `git ls-remote https://github.com/justin-orderathome/cockpit-release.git` 確認連得到發布 repo，把完整的錯誤訊息轉給作者。

**移除**：`claude plugin uninstall cockpit@orderathome`，要連 marketplace 一起拿掉再加 `claude plugin marketplace remove orderathome`。

**之後的更新**不必重裝，見下面的「更新」一節。你的設定、常用 prompt 與 SKILL 覆寫都存在別的地方（`settings.json` 與 `~/.claude/cockpit/`），換版不會被蓋掉。

**裝之前要知道的**：

- cockpit 會在每個 session 的 system prompt 加一段要求，請模型在任務名稱後面寫上預估時間 `(~Nm)`。
- SKILL 說明的翻譯與用法的整理都會用到你的 API 用量，不需要可以在 [設定] 分別關掉。用法第一次會對每個列出的 skill 各問一次 `haiku`（幾十次），之後只有新裝的或 SKILL.md 改過的才再問。
- SKILL 的教學用的是 `sonnet`，一份問一次，輸入最多約 150 KB 的原文，比整理用法貴得多；但只有你在用法頁按下「教學」時才會產生，不按就不花用量。
- 「編輯」與點票開檔是呼叫 VS Code 的 `code` 指令，要先確定終端機裡打得出 `code`。

## 使用

- **開啟面板**：session 開始時自動開啟（可以在 [設定] 關掉）。終端機要 144 欄以上，自動開啟的面板才會停靠在右側；隨時可以用 `/cockpit` 開啟。
- **操作面板**：按 `ctrl+x tab` 讓面板取得焦點，之後就能用下面的快速鍵，Tab／方向鍵移動、Enter 按下。用 `/cockpit` 開啟時會直接取得焦點。

| 範圍 | 按鍵 | 動作 |
| --- | --- | --- |
| 全域 | `1` `2` `3` `4` | 切換到 [任務]／[基本]／[SKILL]／[設定] |
| 全域 | `k`／`j` | 上一頁／下一頁 |
| [任務] | `c` | 清除已完成（含已結束的 subagent 列與它底下的任務） |
| [任務] | `d` | 顯示或隱藏已完成的 effort（有已完成的 effort 時才出現） |
| [任務] | `r` | 重新載入路線圖（有路線圖時才出現） |
| [基本] | `e` | 編輯 `prompts.md` |
| [基本] | `p` | 編輯本專案的 `.claude/prompts.md`（有這個檔案時才出現） |
| [基本] | `r` | 重新載入 |
| [SKILL] | `o` | 進出開關模式（見上方「開關」） |
| [SKILL] | `u`，再按 `q` `r` | 更新用法：快速（只補缺的）／重整（全部重新問一次） |
| [SKILL] | `e` | 編輯 SKILL 覆寫檔 |
| [SKILL] 的用法頁 | `f` `b` `t` | 把這個 skill 填進輸入框／返回列表／教學（沒有就產生，有就打開） |

快速鍵只在面板有焦點時有效，在輸入框打字不會誤觸。

## 設定檔

### 常用 prompt：`~/.claude/cockpit/prompts.md`

第一次按 [基本] 的 `e: 編輯` 時，會建立一份範例。格式：

```markdown
# 票
## 接手這張票
接手 {{票}}，先讀票與規格書，說明你打算怎麼做。

# 審查
## review diff
請 review 目前未 commit 的變更，只列出真正的問題。

## commit 訊息 !
依照目前的變更寫一則繁體中文 commit 訊息，先給我看，不要 commit。

# 規劃
## wayfinder
/mattpocock-skills:wayfinder .scratch/
```

- `# 分組`、`## 名稱`；名稱底下到下一個標題之間的內文就是 prompt，可以多行。
- 名稱結尾加 ` !` 的，點了會直接送出；其餘會填進輸入框。
- 第一個 `#` 之前就出現的 `##`，放在不分組的最前面。
- 常用的 skill 也可以寫成一筆 slash command（如上例的 wayfinder）。
- 可以用 prompt 變數（如上例的 `{{票}}`，見下面）。

目前專案若有 `.claude/prompts.md`（格式相同），會以「本專案」接在全域清單後面。

**prompt 變數**：常用 prompt 裡寫 `{{名稱}}`，cockpit 在 [基本] 填入或送出時換成當下的值，不必每次自己補票的路徑或分支名稱。

| 變數 | 換成 | 取不到 |
| --- | --- | --- |
| `{{票}}` | 主對話最近經手的那一張票（見上方「誰在做這張票」），寫成相對於專案根目錄的路徑，例如 `.scratch/agent-interaction/issues/08-panel-layout.md`；票在專案根目錄外時是完整路徑。subagent 經手的不算，好幾張只取最近一張；結案的票不會被取到 | 主對話還沒經手任何沒結案的票。不會退而去找已認領的票 |
| `{{分支}}` | 目前的 git branch 名稱（點下去時才在 repo 根目錄執行 `git rev-parse --abbrev-ref HEAD`） | 不在 git repo，或 detached HEAD |

- **只認得這兩個名稱**：其他 `{{x}}` 原樣保留，不需要跳脫；同一個變數出現幾次就換幾次。全域與專案的 `prompts.md` 都代換。
- **取不到時**：那個變數的原字留著、填進輸入框（不會悄悄留空），跳 toast「取不到『票』」；兩個都取不到時寫「取不到『票』『分支』」，順序照它們在 prompt 裡出現的先後。名稱結尾 ` !` 的這時也改成只填入、不送出，讓你自己補上再送。
- **都取得到時**：` !` 的直接送出，不先確認；想先看一眼的就別加 ` !`。
- **只有 cockpit 填的才代換**：你自己在輸入框打的 `{{…}}` 不動。說明區顯示的是原文（含 `{{票}}`），不是代換後的樣子。
- 第一次按 `e` 建立的範例附了一筆用 `{{票}}` 的「接手這張票」，開頭的註解也列了可用的變數。

### SKILL 覆寫：`~/.claude/cockpit/skills.json`

在 [SKILL] 按下框線上的「編輯覆寫」（`e`）用 VS Code 打開；檔案還不存在時會先建立一份範例，開頭的 `說明` 列了五個鍵的用法與寫法範例（JSON 不能寫註解，所以放在一個 cockpit 不讀的鍵裡，不需要可以整段刪掉）。存檔後切到別的分頁再切回 [SKILL] 就生效。

```json
{
  "groups": { "mattpocock-skills": "mattpocock" },
  "descriptions": { "mattpocock-skills:wayfinder": "大型工作的地圖" },
  "hidden": ["mattpocock-skills:teach", "builtin-skills"],
  "move": { "gitnexus-*": "gitnexus", "mattpocock-skills:grilling": "my-skills" },
  "categories": { "專案": ["mattpocock-skills"], "工具": ["gitnexus", "builtin-skills"] }
}
```

| 欄位 | 用途 |
| --- | --- |
| `groups` | 組名改成較短的名稱：組的 id（plugin 名稱、來源的 `owner/repo` 或 `move` 開的自訂組）→ 顯示的組名 |
| `descriptions` | 自訂短說明，優先於自動翻譯：skill 完整名稱 → 說明 |
| `hidden` | 要隱藏的 skill（完整名稱）或整組。組的 id 是 plugin 名稱、來源的 `owner/repo` 或自訂組的 id，另外兩組是 `my-skills`、`builtin-skills` |
| `move` | 把 skill 移到指定的組：skill 完整名稱 → 組的 id。列在 [SKILL] 裡的 skill 都能移（個人的、來源組的、plugin 的、內建的），蓋過預設的分組。名稱結尾可以加一個 `*` 比對前綴（`gitnexus-*`；只寫 `"*"` 就是所有 skill），同時符合時完整名稱優先，符合多個前綴時取最長的。組的 id 和現有的組同名就併進那一組，否則開一個自訂組，和 plugin 組一起照字母排，一樣能用 `groups` 改名、用 `hidden` 藏掉。找不到的 skill 安靜略過 |
| `categories` | 把組歸進分類：分類名稱（就是顯示的名稱）→ 組 id 的陣列。有寫時 [SKILL] 的搜尋列下方多一排分類分頁籤，一次看一個分類（見下方說明） |

`move` 的幾個細節：

- `move` 比整組的 `hidden` 優先：從藏掉的組移出來的 skill，會出現在新的組裡；但 `hidden` 裡單獨列名的 skill，移到哪組都照樣藏著。
- 只有 skill 能移：`/clear` 這類內建指令本來就不列在 [SKILL]，寫進 `move` 也不會有作用。
- plugin skill 移到別組後，顯示的名稱照舊省略前綴，所以可能和那組裡另一個同名的 skill 看起來一模一樣；插入輸入框的還是完整名稱，不會選錯。

`categories` 的規則：

- 歸類在分組與 `move` 之後，看的是 `move` 之後的組 id，所以 `move` 開的自訂組也能放進分類。
- 分類照寫的順序排，分類裡的組照寫的順序排；沒寫到的組集中在最後的「未分類」（名稱固定），照原本的順序。所有組都歸好了就沒有「未分類」。
- 一個組只屬一個分類：同一組寫在兩個分類時只算先寫的那個。不存在（或已經藏掉）的組 id 安靜略過，一個組都對不上的分類不出現；分類不能取名「未分類」。
- `hidden` 不收分類名稱（分類名稱可能和組 id 撞名）；組與 skill 照舊用 `hidden` 藏。
- 點分頁籤切換分類，選的分類跨 session 記住。搜尋時不限選中的分類，列出所有有符合項目的分類，組全部展開。
- 沒寫 `categories`、格式不對，或寫的分類都對不上時，[SKILL] 和沒有這個功能時一模一樣。

### 範本：作者整理好的常用 prompt 與 SKILL 覆寫

作者可以在發布版裡附一份範本，同事在 [設定] 按「套用範本」，把自己還沒有的常用 prompt 與 SKILL 覆寫一次加進來。檔案是同事自己的：套用只加不改，不會蓋掉同事改過的東西；作者改了範本，也不會直接改變同事的畫面。

```
│ cockpit 0.9.0  範本有 3 項新的  檢查版本  更新紀錄         │
╰─ 恢復預設值（都是預設）  重新載入 mod ─────────────────────╯
```

（80 欄左右的面板放不下下框線右側，版本那一列退回框內最下面一行；寬的面板疊在下框線右端。）

**同事這一邊**：

- **按鈕**：[設定] 下框線右側、「檢查版本」左邊的「套用範本」。範本裡有還沒套用過的項目時，換成高亮的「範本有 N 項新的」（N 是現在按下去會加進來的項目數），套用後恢復成「套用範本」。剛裝好的同事會直接看到它；它不跳 toast，也不出現在其他分頁。面板太窄、放不下時，跟著版本那一列退回框內最下面一行。這一版的 cockpit 沒附範本時不顯示按鈕。
- **按下去**：一次套用兩個檔案（`~/.claude/cockpit/prompts.md` 與 `skills.json`），不預覽。有東西要加時，寫入前各備份一份 `<檔名>.bak`（每次覆蓋上一份）；本機還沒有那個檔（也從沒套用過），就整份照範本建立（範本開頭的註解、`說明` 與其他鍵都一起帶過來）。專案的 `.claude/prompts.md` 不碰，它本來就能跟著專案 repo 分享。
- **完成時**：toast「範本：加了 2 筆 prompt、1 項 SKILL 覆寫」（作者只附了其中一個範本時只寫那一半）；沒東西可加時寫「範本都套用過了」。
- **出錯時**：兩個檔案各自成敗，一個出錯另一個照常，toast 一起說明，例如「範本：加了 2 筆 prompt；沒有套用 SKILL 覆寫：讀不懂 ~/.claude/cockpit/skills.json，請修好後再按」。檔案存在卻讀不出來、或 `skills.json` 不是讀得懂的格式時，那一半不寫，「範本有 N 項新的」也不算那一半；寫入失敗時說明原因，`.bak` 留著，那一半也不記成套用過，修好再按一次就好。
- **常用 prompt 怎麼合併**：一筆的識別是「分組＋名稱」（名稱結尾的 ` !` 不算，改成直接送出不算改名）。只加入從沒套用過、本機也沒有的；套用過後你刪掉或改名的，不會再加回去。新的放在同名 `# 分組` 的最後，本機沒有這一組就整組接在檔尾。
- **SKILL 覆寫怎麼合併**：

  | 區段 | 規則 |
  | --- | --- |
  | `groups`、`descriptions`、`move` | 只加本機沒有的鍵，本機已有的鍵不動 |
  | `hidden` | 只加本機沒有、也沒套用過的項目：套用過後你取消隱藏的，不會再藏回去 |
  | `categories` | 本機沒有的分類加進來、已有的分類接在最後；兩種都只放「本機哪個分類都還沒放」的組 id（一個組只放一個分類），每個組都已經放過的新分類不加 |
  | `說明` 與其他鍵 | 不動 |

  `groups`、`descriptions`、`move`、`categories` 只看本機現在有沒有：套用過後你把整個鍵或整個分類刪掉，下次按（按鈕也會再亮起來）會再加回來；不想要的話，留著改成自己的值比刪掉好。有加東西時，寫回的排版改成 cockpit 的格式（兩格縮排）。範本裡寫到你沒裝的 skill 或組照樣加進去，`skills.json` 本來就會略過找不到的。
- **範本改了內容、名稱沒變**：你保留自己的舊內容，也不會提示「這筆有新版」。
- **套用紀錄**：套用過哪些項目記在 cockpit 自己的狀態（`$.store` 的 `appliedTemplate`），全域、不分專案。
- **範本怎麼來**：跟著 cockpit 的版本走，你同意的「更新」拿到新版時一起拿到；cockpit 不另外下載。

**作者這一邊（維護範本）**：

1. 在原始碼 repo 的根目錄建 `templates/`，放 `prompts.md` 和（或）`skills.json`，格式和自己的 `~/.claude/cockpit/prompts.md`、`skills.json` 一樣。兩個都可以只放一個；兩個都沒有時同事看不到按鈕。
2. 範本要自己手動寫或從自己的檔案挑著貼過去：發布不會複製你本機 `~/.claude/cockpit/` 的檔案，因為發布 repo 是公開的。放進去之前檢查沒有路徑、帳號這類私人資訊。
3. commit 到 `main`。發布的內容取自 commit，不是工作目錄，沒 commit 的範本不會帶出去。
4. 照下方「發布」改版本號、寫更新紀錄、發布；`scripts/publish.mjs` 會把 `templates/` 一起放進發布 repo（原始碼 repo 沒有這個資料夾時照常發布，只是沒有範本）。同事更新之後，有新項目時「範本有 N 項新的」會亮起來。
5. **改內容要改名**：同事已經套用過的那一筆不會被換掉。要讓同事拿到新內容，就把它當成新項目、換一個名稱（prompt 換「分組＋名稱」，SKILL 覆寫換鍵）。從範本拿掉的項目也不會從同事的檔案消失。
6. **先在自己這裡看一次**：用資料夾載入 cockpit（`CLAUDE_CODE_PLUGIN_DIRS`）時讀的是那個資料夾的 `templates/`。範本裡跟你自己的檔案同名的項目算已有，所以在你自己的電腦上按鈕通常只是「套用範本」、不會一直亮著。

### 面板參數

在 [設定] 分頁或 `/config` 都能改，兩邊改的是同一份值，存在 `settings.json` 的 `pluginConfigs`。改了立即生效。改過（不是預設值）的參數，值後面有一個暗色的「•」，還是預設值的標籤是暗色。下框線左端有「恢復預設值（N 項）」（寫出會改回幾項；都是預設值時寫「都是預設」，按了沒有作用）與「重新載入 mod」（面板狀態不對時救急用：跑內建的 `/reload-plugins`，所有 mod 一起重載，cockpit 重載完會跳「cockpit 已重新載入」）；下框線右端是目前裝的版本（`cockpit x.y.z`），後面有「套用範本」（這一版附了範本才有，見上方「範本」）、「檢查版本」與「更新紀錄」（面板太窄、放不下時，版本這一列退回框內最下面一行）；發布的版本和裝的不同時，版本號後面會留著高亮的「有新版 x.y.z」，已經下載的話是「x.y.z 已下載，重開後換上」、按鈕換成「立即換上」（見下方「更新」）。

| 參數 | 預設 | 選項 |
| --- | --- | --- |
| 強調色 | `claude` | 幾個主題色 |
| 黃色門檻 | 50% | 40–90% |
| 紅色門檻 | 80% | 40–90% |
| toast 門檻 | 80% | 關／70／80／90% |
| 自動開啟 | 開 | 開／關 |
| 預設分頁 | 上次停的 | 上次停的／任務／基本／SKILL |
| inline 行數（面板顯示在輸入框上方時，下方區塊最多幾行） | 8 | 4–12 |
| 翻譯說明 | 開 | 開／關 |
| 整理用法 | 開 | 開／關 |
| 排列方式（[SKILL] 一組裡的 skill 怎麼排） | 橫向 | 橫向／垂直 |
| 自動更新（開場查到不同的版本時自己下載，下次開啟換上；作者退版是例外，關著也會自己下載） | 關 | 開／關 |

### 更新

發布的版本以公開的發布 repo `justin-orderathome/cockpit-release` 裡 `plugin.json` 的 `version` 為準。檢查時先請 Claude Code 把 marketplace 拉到最新，再讀它在本機的那一份，所以問你的版本號就是實際會換上的那一版。比的是「和你裝的一不一樣」，不是「比較新」，所以作者退回舊版時也會跟著換。

- **開場檢查**：從 marketplace 裝的 cockpit 每次開場都在背景看一次發布的版本，「自動更新」開不開都看，不必記得去按「檢查版本」。它排在開場的最後、面板開出來之後才開始，不會讓面板比較慢出現。距離上次檢查不到四小時就跳過（一天開很多個 session 時不會每次都去看）；手動按「檢查版本」不受這個限制。查不到（沒有網路、指令失敗、逾時）就安靜略過，下次開場再試。
- **有新版時**：發布的版本和裝的不同、而「自動更新」關著時，不會下載，只跳一次「cockpit 有新版 x.y.z，到 [設定] 按「檢查版本」換上」。同一個發布的版本只提示一次；作者再發下一版時，那一版再提示一次。這裡說的是發布的版本比裝的新；比裝的舊（作者退版）見下面的「退版」。
- **留著的標示**：錯過提示也看得到。發布的版本和裝的不同時，兩處同時留著標示：[設定] 版本號後面高亮的「有新版 x.y.z」，以及分頁列的「設定」變色並帶一個「●」（停在別的分頁也看得出來）。標示不能手動點掉，在詢問選「先不要」也還在；換上之後（裝的和發布的一樣了）才消失。上次查到的發布版本記在 cockpit 的狀態檔，所以四小時內重開、沒有重新檢查時標示也還在。「自動更新」已經把發布的版本下載好時，版本號後面的字換成「x.y.z 已下載，重開後換上」，那一列的按鈕從「檢查版本」換成「立即換上」。
- **檢查版本**：[設定] 版本號後面的按鈕。按了去看發布的版本：一樣就說已經是發布的版本；不一樣就問「要立即更新嗎？」，選「立即更新」會下載新版並重新載入 mod，換好後跳「cockpit 已更新到 x.y.z」；選「先不要」不會下載，標示留著。升版時問句下面會列出你裝的版本之後、到發布的版本為止每一版的更新紀錄（新的在前，最多六條，超過時最後一行是「其餘見更新紀錄」）；發布的那一版沒有更新紀錄就只問不列。發布的版本比裝的舊（作者退版）時，問的是「發布的版本已退回 x.y.z，要立即換上嗎？」，選項是「立即換上」，不列更新紀錄。
- **更新紀錄**：版本號那一列的另一顆按鈕，用 VS Code 打開你裝著的那一版附的 `CHANGELOG.md`，隨時查得到每一版改了什麼；那一版沒有附就跳「這一版沒有更新紀錄」。
- **自動更新**（[設定]，預設關）：打開後，開場檢查查到不一樣的版本就在背景下載，跳「cockpit x.y.z 已下載，下次開啟時換上」，標示換成「已下載」；不會打斷正在用的這個 session。同一版只下載一次，同一個發布的版本也只提示一次，不管是哪一句：已經跳過「有新版 x.y.z」或在「檢查版本」被問過的那一版，之後下載好了只換標示，不再跳「已下載」。背景的下載失敗時不講失敗的原因，改跳那一句「cockpit 有新版 x.y.z，到 [設定] 按「檢查版本」換上」（一樣每版一次），標示維持「有新版 x.y.z」；這次不算檢查過，下次開場不必等四小時就會再試。
- **退版**：作者收回出事的版本時，發布的版本會比你裝的舊。這時開場檢查不管「自動更新」開不開都在背景下載，跳一次「cockpit 發布的版本已退回 x.y.z，已下載，下次開啟時換上」，下次開啟 Claude Code 就退回那一版；想當下就換，按「立即換上」。這是「自動更新」關著時唯一不問你就下載的情況：出事的版本不該留在你的機器上等你有空才換。標示寫的是「已退回 x.y.z，重開後換上」，按鈕是「立即換上」；背景的下載失敗時不講失敗的原因，改跳一次「cockpit 發布的版本已退回 x.y.z，到 [設定] 按「檢查版本」換上」，標示是「發布的版本已退回 x.y.z」，按鈕是「檢查版本」（按了會問要不要立即換上）；這次不算檢查過，下次開場不必等四小時就會再試。換上之後跳「cockpit 已退回 x.y.z」，標示消失。版本號不是純數字、比不出新舊時照升版處理，不會自己下載。
- **立即換上**：新版已經下載、還沒換上時，[設定] 版本號那一列的按鈕。按了不會再問，直接重新載入 mod，當下就換成新版，不必重開 Claude Code；換好後跳「cockpit 已更新到 x.y.z」（退版是「cockpit 已退回 x.y.z」），標示消失。不按也沒關係，下次開啟 Claude Code 時一樣會換上。已下載之後作者又發了別的版本時，已下載的那一版不算數：標示照新的發布版本重新判斷（回到「有新版」，等下載好再變成「已下載」）。
- **下載之後作者又收回**：已經下載了 x.y.z 還沒換上，發布的版本又變回你現在裝的這一版時（作者把 x.y.z 收回了），cockpit 會把磁碟上的那一份換回發布的版本，免得下次開啟換成被收回的 x.y.z。開場檢查與手動按「檢查版本」都會做，不會跳訊息；沒換成就安靜略過，下次開場（不必等四小時）或下次按「檢查版本」再試。
- **換了版本會講**：不管是怎麼換的，開場時發現版本和上次不一樣，就跳「cockpit 已更新到 x.y.z」；版本號變小（作者退版）時跳「cockpit 已退回 x.y.z」。
- **只對從 marketplace 裝的有效**：檢查是跑 `claude plugin marketplace update`，更新是跑 `claude plugin update`。用資料夾加 `CLAUDE_CODE_PLUGIN_DIRS` 載入的那一份，「檢查版本」改成上網看發布 repo（剛發布的幾分鐘內可能還是舊的），只會告訴你發布的是哪一版，要自己換；它開場不檢查、沒有標示，自動更新對它也沒有作用。
- 連不上會說查不到，不影響其他功能。

### SKILL 說明的翻譯

讀到 skill 清單時，cockpit 會把還沒翻過的英文說明，每 10 筆一批交給 `haiku` 翻成繁體中文（已經是中文的略過）。結果會快取，之後只有新裝的 skill，或說明有改的，才會再翻。翻譯會用到你的 API 用量，不需要的話可以在 [設定] 關掉。

### SKILL 的用法

說明通常只有一兩句，作者規劃的觸發詞、參數、模式與步驟多半寫在 SKILL.md 的內文。讀到 skill 清單時，cockpit 會在說明翻完之後，把每個 skill 的 SKILL.md 交給 `haiku` 整理成四項用法，一個 skill 問一次，同時最多 3 個：

| 項目 | 內容 |
| --- | --- |
| 何時用 | 觸發詞與適用的情境 |
| 怎麼叫 | 參數與模式 |
| 會做什麼 | 作者規劃的步驟或產出 |
| 搭配 | 原文裡點名的其他 skill |

原文沒寫的那一項不顯示；觸發詞、指令與 skill 名稱保留原文。

- **怎麼看**：有用法的 skill 名稱後面有 `?`，點了進用法頁；滑鼠停在名稱上時，說明區的標題也會提示有幾項用法，或「用法整理中…」。用法頁放不下時用翻頁鍵。
- **原文從哪裡來**：使用者自己的 skill（`~/.claude/skills/`，含 claude.ai 同步的）、plugin 的 skill（依 `installed_plugins.json` 找安裝目錄）與專案的 skill（`.claude/skills/`）讀 SKILL.md；只讀 SKILL.md 本身，不讀它引用的其他檔案。找不到檔案的（例如內建 skill）改用說明來整理，用法頁會標示「只依說明整理」。
- **什麼時候重新整理**：結果會快取。只有新裝的 skill、SKILL.md 的內容改過，或 cockpit 更新了整理的規則時，才會再問模型；plugin 升級但 SKILL.md 沒變不會。
- **失敗時**：單一 skill 失敗就跳過；連續 3 個失敗或模型沒回應（多半是用量用完）就整輪停下，已整理的保留。
- **更新**：一個 session 只會自動整理一輪。之後要再整理（新裝了 skill、上次整理到一半停下）就按下框線左端的「更新用法」，再選一個：**快速**只補還沒有的與原文改過的，已經有的不重做；**重整**不看快取，每個 skill 都重新問一次（覺得整理得不好時用，會花掉幾十次 `haiku` 的用量）。重整到一半停下時，還沒輪到的保留原本的用法。
- **關掉**：[設定] 的「整理用法」。關掉後不再問模型，也不顯示 `?`；已存的用法留著，重新打開就直接用。它與「翻譯說明」互不影響。

### SKILL 的教學

說明和用法都是摘要，夠用來想起來，不夠用來學會。教學是第三層：一份拿來學這個 skill 的繁體中文文件。

| | 什麼時候看 | 長度 | 怎麼來 |
| --- | --- | --- | --- |
| 說明 | 已經熟，掃一眼 | 一兩句 | 自動翻譯 |
| 用法 | 快要用，確認怎麼叫 | 四項條列 | 自動整理 |
| 教學 | 第一次學，或忘了回來讀 | 一份文件 | 你按了才產生 |

- **怎麼產生**：在用法頁按「教學」（`t`）。cockpit 把原文交給 `sonnet` 寫成一份 markdown，存檔後用 VS Code 打開。產生要等一陣子，這段時間按鈕會顯示「教學產生中…」，可以離開用法頁做別的事；同一時間只產一份。已經有教學時，再按就直接打開，不會重產；檔案本來就開著的話編輯器只會切到那個分頁，面板會跳「教學已在編輯器打開」。
- **內容**：固定六章（做什麼、什麼時候用與不該用、怎麼叫、怎麼進行、範例、搭配與後續），原文沒寫的那一章省略。指令、參數與 skill 名稱保留原文。作者沒寫範例時，模型會依原文寫示意的範例，標題都標「（示意）」；其他章節只講原文有的。
- **檔案在哪**：`~/.claude/cockpit/tutorials/<skill 名稱>.md`（名稱裡不能當檔名的字元會換掉，例如 `impeccable:impeccable` 是 `impeccable%3Aimpeccable.md`）。檔案是你的，可以自己加筆記。開頭有幾行資訊，記著它是依哪一版原文產的。
- **讀哪些檔**：SKILL.md，加上它用連結點到、而且在這個 skill 自己資料夾底下的文件（`.md`、`.mdx`、`.txt`），只跟一層。合計上限 150 KB，依出現的順序讀，放不下的與讀不到的會列在教學開頭。找不到 SKILL.md 的 skill（例如內建的）沒有「教學」按鈕。
- **原文更新之後**：不會自動重產。舊的教學照樣可以打開，用法頁會標「教學：原文已更新」。要重來就按「重新產生」，再按一次「覆蓋」確認；重新產生是整份覆蓋，你加的筆記不會保留。
- **失敗時**：跳 toast 說明原因，不會留下半成品；重新產生失敗時原本的檔案不動。
- **沒有開關**：不按就不讀檔、不問模型。不過教學的按鈕在用法頁上，[設定] 的「整理用法」關掉時進不了用法頁，也就按不到。

## 疑難排解

**面板的框線破掉、有殘影**（VS Code 終端機）：右框線有些行不見或偏一格，對話區右緣出現零星的「│」。原因是 VS Code 的 `terminal.integrated.gpuAcceleration` 設成了 `off`，終端機改用 DOM 繪製，中文與符號混排時位置會偏。到 VS Code 設定搜尋 `terminal gpu`，把「Terminal › Integrated: Gpu Acceleration」改回 `auto`（預設值），改完立刻生效，不必重開。

### 發布

```
node scripts/publish.mjs --dry-run   # 預演：檢查照跑，印出會發布哪個 commit、哪個版本號、哪些檔；不推、不打 tag
node scripts/publish.mjs             # 發布目前的 HEAD
node scripts/publish.mjs v0.6.0      # 退版：重發先前發布過的那一版（帶它的 tag 名稱）
```

發布之前先做三件事：在 `.claude-plugin/plugin.json` 改版本號（只有這一處要改）、在 `CHANGELOG.md` 加一個標題剛好是版本號的段落（`## x.y.z`）、commit 並推到 `main`。指令不替你改版本號，也不替你 commit。

指令會依序做：

1. **檢查**，全部通過才往下：版本號的 tag 沒有打在別的 commit 上、工作目錄是乾淨的、HEAD 已經推到遠端的 `main`、更新紀錄有這一版的條目，再跑上面的驗證、測試與型別檢查。
2. 把發布 repo 重新 clone 到暫存資料夾，整個換掉裡面的 `cockpit/`（`.claude-plugin`、`hooks`、`types`、`templates`（範本，原始碼 repo 有才帶，見上方「範本」）、`README.md`、`LICENSE`、`CHANGELOG.md`，內容取自 commit，不是工作目錄），並把根目錄的 `LICENSE` 換成同一份。marketplace 的目錄檔與根目錄的 README 不碰。
3. 發布的版本和這次的版本號一樣、內容卻不同時停下來，請你先改版本號：同事機器上的快取是照版本號認的，版本號沒變就拿不到新內容。
4. commit（訊息是「cockpit x.y.z（原始碼 abc1234）」）並推到發布 repo，再在被發布的 commit 打 `vx.y.z` 並推到原始碼 repo。這個 tag 就是之後退版的目標。

任何一步失敗都會印出失敗在哪一步，結束碼不是零。發布 repo 推上去之後才失敗（例如 tag 沒推成功）的，直接重跑：內容已經一樣時不會多一個 commit，只補上 tag。

**退版**：發出去的版本出事時，帶上先前那一版的 tag 名稱再跑一次（`git tag -l` 看有哪些），發布的版本就換回那一版，內容與版本號都取自那個 tag 指向的 commit。這是出事時用的，所以不要求工作目錄乾淨、不要求已推送，也不跑驗證、測試、型別檢查與更新紀錄的檢查，手上改到一半也能立刻退。發布 repo 照樣往前多一個 commit（歷史不改寫），tag 已經在就不再打；同事那邊不管「自動更新」開不開都會跟著退回。可以先加 `--dry-run` 預演。只收版本的 tag（`vx.y.z`），分支與 commit 的 hash 不收；指定的 tag 不存在會停下來。

**用過的版本號不再用**：退版之後修好要再發，一定要換一個新的版本號，就算出事的那一版只發出去幾分鐘。裝過那一版的機器快取是照版本號認的，同一個版本號換了內容，它們會沿用出事的那一份。指令會擋下來：版本的 tag 已經打在別的 commit 上時拒絕發布。

`--release-repo <位置>` 與 `--skip-checks`（跳過驗證、測試與型別檢查）只給測試用。測試會建兩個暫存的 git repo（原始碼 repo 與本機的 bare 發布 repo）讓指令真的跑完，不會碰到真的發布 repo。

`register.tsx` 很長是引擎的規定造成的：`$` 只能傳給同一個檔案裡宣告的函式，atom 也要寫在用它的檔案裡，兩者都不會跟著 import 進別的檔案（違反時 mod 會載入失敗）。所以碰到引擎的程式留在那裡，不碰引擎的判斷（顯示哪些字、多寬、幾行、何時重讀）才拆到別的檔案，也才有直接的測試。

型別檢查用的 `tsconfig.json`，延伸的是 `.claude-plugin/types/` 裡的型別設定。那個資料夾由 Claude Code 在載入 mod 時自動產生（已加進 `.gitignore`），所以要先載入過一次才能做型別檢查。

面板測試裡的 cockpit 是從資料夾載入的，測試工具也沒有辦法指定 plugin 的資料夾。更新的規則在 `tests/updater.test.ts` 直接測，不必經過面板；面板測試只驗「從 marketplace 安裝」時標示與按鈕的接線，這時在測試的環境變數裡設 `COCKPIT_TEST_PLUGIN_ROOT`，值是假裝的安裝資料夾（`…/plugins/cache/<marketplace>/<plugin>/<版本>`）；`tests/pane.test.tsx` 的 `marketplaceInstall` 就是這樣做的。它只拿來判斷這一份是從哪裡裝的，讀檔仍然讀真的資料夾；沒設（正式環境）時看的是真的資料夾。
